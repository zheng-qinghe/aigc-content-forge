# historical-parallels

> **历史类比镜** — 当你说出自己的困境，沿中国与国际全部历史纵深，找出真正处境相似的人，
> 分别考据他们**当时如何应对**与**事后如何诠释这段经历**，并揭示两者之间的落差。

一个 Agent Skill。做的是历史研究里最难的一件事：**把「事实」和「后来人讲的故事」分开**。

---

## 它解决什么问题

面对困境时，人们本能地想找"有人跟我一样"。但市面上的答案几乎都有两个毛病：

| 毛病 | 表现 |
|---|---|
| **幸存者偏差** | 找到的全是"坚持到最后"的成功者，你以为是自己不够坚持 |
| **叙事缝合** | 把史料拼成流畅的故事，细节其实是编的；把"他做到了"当成"他做对了" |

本 skill 的处理方式：

1. **强制包含失败案例** —— 每个回答必须有人结局不佳，否则作废。
2. **三层取证** —— L1 当时行为 / L2 当时自述 / L3 后世诠释，分开写，不许揉成一句
   "他从容不迫地坚持了下来"。
3. **落差检验** —— L1 与 L2/L3 的差距本身就是最有价值的信息。
   一个人在低谷时说"我从未动摇"和他在低谷时实际写下的"我夜不能寐"之间的差距，
   往往比任何结论都更能回答问题：**那揭示了人如何给自己讲一个能继续走下去的故事。**
4. **时代归因** —— 区分"个人可控"与"时代给的红利/劫难"，防止把结构问题个人化。
5. **必写"不适合你的那部分"** —— 主动指出哪个类比会失效、为什么。

## 设计上的两个取舍

**为什么不叫"励志案例库"？**
因为励志会把 L1（他做了什么）和 L3（后人怎么讲）混为一谈。
本 skill 的核心价值恰恰在这两者的**落差**里，不在结论里。

**为什么强制写"不适合你的那部分"？**
历史不能直接当行动指南。杜利欧的解法（分阶段让权、变现、保留机构）
依赖"机构本身有价值"这个前提；**濒死3 个月的公司没有这个前提**。
不主动说出这个边界，输出就退化成鸡汤。

## 与已有 skill 的边界

| | `case-finder` | **本 skill** |
|---|---|---|
| 取材 | 当代商业案例 | 全部历史，纵深不限 |
| 对象 | 公司为主 | **人**为主 |
| 结构 | 好结果 / 坏结果二分 | **L1 行为 / L2 自述 / L3 后世诠释** |
| 落点 | 具体解决办法 | 处境类比 + 叙事落差 |

两者互补：先用本 skill 找**处境可比的人**，再补 case-finder 找**当代可执行案例**。

## 安装

本 skill 位于 `aigc-content-forge` 仓库的 `skills/historical-parallels/` 目录下。

```bash
# 从本仓库取该 skill 到本机 skills 目录
git clone --filter=blob:none --sparse https://github.com/zheng-qinghe/aigc-content-forge.git
cd aigc-content-forge
git sparse-checkout set skills/historical-parallels
cp -R skills/historical-parallels ~/.workbuddy/skills/
```

或直接复制 `skills/historical-parallels/` 整个目录到 `~/.workbuddy/skills/` 下即可。

> 用 `--filter=blob:none --sparse` 是因为本仓库还包含大量 AIGC 媒体素材（图文/视频/音频），
> 全量 clone 会拉取几十 MB 与本 skill 无关的文件。
