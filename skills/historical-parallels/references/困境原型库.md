# 困境原型库

> 用途：把用户说的问题，翻译成**可与史料匹配的结构性处境**。
> 这是全流程最易草率的一步 —— 抽象错了，后面搜的全废。

---

## 为什么必须抽象

用户会说：「我快撑不住了」「团队要散」「我是不是不适合干这行」。
这些是**感受的语言**，不是**处境的语言**。史料里不会有"快撑不住了"这种处境，
只有"某人在某年某月失去了某样具体的、被剥夺的东西"。

**抽象的目标**：把感受语言换成「位置 + 压力 + 选择权 + 时间」。

---

## 六轴速查表

| 轴 | 维度 | 关键问题 | 常见误判 |
|---|---|---|---|
| **① 位置** | 新手 / 掌权者 / 边缘人 / 中间层 / 已出局 | 他能决定谁的死活吗？ | 用户常把"我说了算"当成"我全责"，实为中间层 |
| **② 压力源** | 资源 / 权力 / 道德 / 认知 / 关系 / 意义 | 压力是**会自己变好**还是**越拖越死**？ | 把资源问题当意义问题（其实是账要断了） |
| **③ 期限** | 一夜 / 一周期 / 一生 / 一时代 | 决策窗口还剩多久？ | 用户以为"还有时间"，实则窗口已关 |
| **④ 选择权** | 可逆 / 不可逆但可止损 / 已被剥夺 | 什么已经不可能了？ | 幻想"还能全盘重来" |
| **⑤ 关系** | 对上 / 对下 / 对平级 / 对市场 / 对自己 | 冲突发生在哪个方向？ | 以为是"和人的冲突"，实为"和自己的冲突" |
| **⑥ 认知** | 已知 / 已知但不愿承认 / 尚未察觉 | 真相需要勇气才能面对吗？ | 用户已知道答案但想要许可 |

**轴②的六个子型**（最常用，展开）：

| 子型 | 特征 | 典型误判 |
|---|---|---|
| **资源枯竭** | 钱/时间/人手/注意力见底 | 以为"再努力点"能解决，其实是算术问题 |
| **权力博弈** | 有对手、有筹码、规则不清 | 以为讲道理能赢，没意识到在博弈 |
| **道德两难** | 两个都对的东西在互斥 | 以为是"选错了"，其实是"必然要牺牲" |
| **认知颠覆** | previously 相信的东西被推翻 | 以为只是"调整策略"，实为地基塌了 |
| **关系决裂** | 信任/共同体破裂 | 以为只是"沟通问题"，实为价值观分歧 |
| **意义丧失** | 目标本身不再值得 | 以为是"不够努力"，实为动机源头已断 |

## 处境白描模板

抽象完成后，**必须向用户复述这句话并请其确认**。

### 模板

> 你面对的不是「{用户原话的表层描述}」，而是：
> **「{时间尺度}内，{位置}的{人}，发现{具体被剥夺/被推翻的东西}；
> 而{他能做的事}受限于{不可抗的约束}；
> 他必须在{期限}前决定{那个不可逆的选择}。」**

### 三个例子

| 用户原话 | 处境白描 |
|---|---|
| 「公司快撑不住了，合伙人要撤」 | 你面对的不是"公司不行"，而是：**你是共同创始人（三个人里排第二的中间层），在现金还能撑 4 个月时发现合伙人的退出你拦不住；退出意味着你要独自承担此前由三个人分担的债务；而你手里只有"接盘"或"跟着走"两个选项，且都不可逆，窗口是 3 周。** |
| 「考研没考上，我不知道该不该二战」 | 你面对的不是"考砸了"，而是：**你是第一次把全部筹码压在一个有明确 deadline 的二元结果上；你在结果公布后的第 3 天提出这个问题，说明你还处于损失急性期；而你真正在决定的是"要不要承认这条路已经关闭"。** |
| 「团队越来越难带，我每天都很累」 | 你面对的不是"团队不行"，而是：**你是中层管理者（对下有责任、对上没有授权），面对的是结构性问题（激励与权责不匹配），而非人的能力问题；而你每天的疲惫来自"用个人能力填补制度缺口"这个不可持续的模式。** |

### 白描的三个检验

1. **具体性**：白描里必须出现具体的、可被史料匹配的名词（不是"处境不好"，是"现金还能撑 4 个月"）。
2. **可证伪**：用户如果说"不对，我没这个限制"，白描就该被推翻。如果怎么推都不倒，说明太模糊。
3. **不含建议**：白描只描述，不评判、不给方案。混入建议会污染后面的检索。

---

## 抽象时的三个常见错误

| 错误 | 表现 | 纠正 |
|---|---|---|
| **把感受当处境** | 白描里出现"焦虑""迷茫""内耗" | 换成具体：什么在流失？多久流失多少？还能撑多久？ |
| **过早共情** | "我理解你现在很难" | 这不是抽象，是安慰。抽象要冷：只描述结构 |
| **单一轴归因** | 只看"压力源=资源"就下结论 | 四轴各问一遍，压力源常常是次要因素 |

## 当用户描述模糊时

用户常常自己也说不清。此时**不要追问到用户崩溃**，用默认值先给出白描，让用户否决：

> 我先按我的理解复述一遍，你看看对不对：
> 「{白描}」
> 如果不对，直接告诉我哪里不对 —— 尤其告诉我"压力到底是钱的问题还是意义的问题"，
> 这个答案会完全改变我找谁。

同时可以用**结构化追问**帮用户自己澄清（一次只问一个，别做问卷）：

- 「如果这件事三个月后自动消失，你还会难受吗？」（测意义 vs 资源）
- 「你最不能接受的是损失本身，还是被别人看见你损失了？」（测资源 vs 关系）
- 「有没有一个期限，过了就彻底没戏了？」（测是否真的存在窗口）
