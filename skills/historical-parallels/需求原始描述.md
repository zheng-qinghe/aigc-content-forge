# 需求原始描述

> 本文件保留这个 skill 的**原始需求文本**，用于日后回溯设计意图：
> 这个 skill 要解决的到底是什么问题、有哪些要求是原话里的、哪些是实现时补的。

---

## 一、用户的原始提示词（原话）

> 生成这样的一个 skill，当我向你诉说我面临的问题的时候，你对于我的问题寻寻找中国和国际范围内全部历史
> 时间线中的知名人物都有哪些人是有过这样的经历，他们分别在当时是如何应对，之后又是如何诠释自己的这段经历的
> 然后上传到我 https://github.com/zheng-qinghe/aigc-content-forge 这个仓库中
> 你看看这个仓库是否合适 不合适就新建一个仓库

## 三、实现时补的内容（原话未要求，但为满足质量而加）

以下是为了让 skill 真正可用而**额外设计**的，不属于原始需求的直接复述：

| 补充项 | 为什么必须加 |
|---|---|
| **三层取证架构**（L1/L2/L3） | 原话要求 A 和 B 恰好对应 L1+L2 与 L3，明确分成三层可防止两者被揉成一句鸡汤 |
| **落差检验** | 落实需求 A 与 B 的"**对照**"关系——两者的差距本身是最有价值的信息，这是本 skill 的差异化内核 |
| **强制包含失败案例** | 修「幸存者偏差」：只找到"坚持到最后"的人，会让用户误以为是自己不够坚持 |
| **金句幻觉禁令** | 修「史料编造」：任何引语必须能指出处，指不出就删 |
| **时代归因**（个人可控 / 时代红利 / 时代劫难） | 修「把结构问题个人化」：防止把"生于乱世"当成个人勇气 |
| **必写"不适合你的那部分"** | 修「历史当行动指南」：历史条件不可直接迁移，防输出退化成励志读物 |
| **处境白描（六轴抽象）** | 前置步骤：不把用户原话拿去搜（字面匹配失效），先抽象成可与史料匹配的结构 |
| **边界声明**（不诊断、不揣测心理） | 需求 7 涉及用户情绪状态，需划清"照见处境"与"心理干预"的界 |

## 四、实现过程中对需求的两次修正

1. **仓库适配判断** —— 初次评估结论是"不合适、建议新建仓库"（因 `aigc-content-forge`
   是图文/视频/音频的**产物仓库**，与 skill 的方法论性质不同）。
   用户最终决定：**不新建，在本仓库内新建 `skills/` 子目录存放**。
   → 故本 skill 路径为 `skills/historical-parallels/`。

2. **需求 A 的粒度** —— 原话"当时是如何应对"实际包含两层不同性质的信息：
   - 他**做了什么**（行为事实）
   - 他**当时如何解释自己的动机**（自我陈述，且带修辞场合）
   → 故拆为 L1（行为）与 L2（自述）。若只做一层，必然会把他的自我辩解当成事实。
